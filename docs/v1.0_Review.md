# Creature AI Framework v1.0 — 仕上げレビュー

## 仕上げフェーズで行ったこと

1. **ログの一元管理**: `CreatureCore.debugLog`(既定 ON)を追加。全コンポーネントは
   起動時にこの値を読み、`[Brain]/[Target]/[Move]/[Action]/[Threat]` 等の動作ログを
   一括で ON/OFF できる。公開ワールドでは OFF 推奨。冗長だった Animator の
   モーション変化ログは削除(HUD/Scene 表示で確認できるため)。
   設定ミスを示す警告(Profile 未検出・Registry 未検出)は常時出す。
2. **対応表の一本化**(Phase 6 で実施済み): `GoalName`/`NeedForGoal` は
   `CreatureBrain` の唯一の定義を各層が参照。重複なし。
3. **複数匹対応の確認と改善**: `2. テスト用の猫を作成` を、既存猫の数だけ
   名前・位置をずらして追加する方式に変更(餌・ベッドは共有)。占有(予約)で
   取り合いにならないことを構造的に保証。
4. **Inspector 整理**: 各コンポーネントに `[Header]`/`[Tooltip]`(日本語)を付与済み。
   実行時に代入する参照は `[HideInInspector]` で隠し、SDK 利用者が触る値だけを露出。

## アーキテクチャの評価

### 良い点(v1.0 として妥当)
- **責務が層で明確に分離**。判断=Brain、実行=各層、危険検知=Threat、
  指揮=Core、性格=倍率提供。1クラス1責務が概ね守られている。
- **単一の中断経路 `AbortCurrent()`** と **明示状態 `AgentState`** により、
  割込み(Flee)が解放漏れなく動く。占有解放は `ReleaseTarget()` の1経路のみ。
- **拡張点が局所化**: Utility 化は `Brain.ScoreOf()`、Goal/Need 追加は enum+対応表、
  動作追加は `MotionKind`+決定表、性格は倍率追加 —— いずれも1〜数箇所で済む。
- **性格が「係数」注入**なので、判断ロジックを汚さずに個体差を出せる。
  Memory/学習も同じ入口(倍率)に係数を足すだけで載る。
- **セットアップが自動化**(Program Asset 生成・Cat 組み立て・Animator 生成・
  キャッシュリセット)されており、UdonSharp 特有の落とし穴を利用者が踏まない。

### 既知の割り切り(v1.0 として許容、将来対応)
- **NeedsData の要素数が定数**で NeedType と二重管理。Need 追加時に両方直す
  (ドキュメント化済み。Udon で enum 長を実行時取得できないための割り切り)。
- **Registry の再取得**: 選出中の Registry が無効化されると登録済み Point が失われる
  (Sensor は Find で復帰するが Point は再登録しない)。単一猫では無害、
  多数の猫が動的に有効/無効化されるワールドで顕在化しうる。
- **Profile 構造変更でシーンの値がリセット**されうる(配列化など)。SDK として
  バージョン間の移行が必要になったら `configVersion` 方式を足す。
- **逃走は最小実装**(ジグザグ化済みだが、障害物回避・隠れ場所選択は無い)。

## 今後追加しやすい機能(設計変更なしで載る)

| 機能 | 追加の仕方 | 触る場所 |
|---|---|---|
| Water/Fun/Social など新 Need | enum+対応表+NeedCount、値はウィンドウ | NeedType/Goal/対応表/NeedsData |
| 新しい動作演出(毛づくろい等) | MotionKind+決定表+Animator 状態 | MotionKind/CreatureAnimator |
| Player Interaction(対人関係) | PlayerRelationshipManager を足し、ThreatEvaluator の反応距離や新 Goal(ApproachPlayer)に反映 | Threat/Brain/新クラス |
| DangerSpot(危険地点) | 危険地点を ThreatEvaluator.Check() で脅威源に合成 | ThreatEvaluator |
| Memory(記憶) | 「怖かった場所/餌のあった場所」を覚え、Personality と同じ「倍率」入口に係数を足す | 新クラス+各層は不変 |
| Utility AI | Brain.ScoreOf() に距離・時間帯・性格・記憶の項を足す | CreatureBrain のみ |
| マルチプレイヤー同期 | Owner 権威(仕様8章)。占有はローカル完結のまま位置/状態を同期 | 配線のみ |

いずれも **既存クラスの一部メソッド追加 or 新クラス追加**で収まり、
層構造そのものの作り直しは不要。

## v1.0 として「不足している」点と理由

以下は v1.0 の範囲外として意図的に見送ったもの(理由付き)。実用上は
「単一クライアントでの生活・危険回避・個体差」までを v1.0 とする判断。

1. **マルチプレイヤー同期の実配線**(`[UdonSynced]`)。
   理由: 仕様8章どおり「1クライアントで完成させてから」着手する方針。
   現状は Owner 権威前提でローカル完結(占有も同期不要な設計)。公開して
   複数人が入るワールドでは、位置・状態の同期配線が別途必要。
2. **障害物回避 / NavMesh 移動**。
   理由: 仕様で NavMesh は任意の後付け。現状は簡易ステアリングで、壁を貫通する。
   平らなテスト空間では問題ないが、複雑な地形では移動が破綻しうる。
3. **記憶・学習(Memory)**。
   理由: v1.0 は「係数で個体差」までとする方針(ユーザー指定)。土台は
   Personality と同じ入口で用意済み。
4. **対人関係(慣れ/信頼)と ApproachPlayer**。
   理由: 仕様7章の関係4段階は未実装。ThreatEvaluator が受け皿を用意済みで、
   次フェーズで自然に載る。
5. **音・パーティクル等の演出、頭上デバッグ HUD の本番用洗練**。
   理由: v1.0 はロジックの完成を優先。表示はデバッグ用の簡易版。

### 結論
**単一クライアントで自律生活・危険回避・個体差まで動く「v1.0」として公開可能**。
公開ワールドで複数人が同時に見る用途では、上記1(同期)を追加してから
公開するのが望ましい。2〜5 は用途に応じて後付けでよく、いずれも大規模な
設計変更を伴わない。
