# Creature AI Framework v1.1 — アセット対応の土台整備

v1.0(単一クライアントで自律生活・危険回避・個体差)を土台に、**「アセットが
増えてもコードを書き換えずに使える」** ことを最優先に、対応関係(対応表)を
1 箇所へ集約した。新しい Action・モーション・地点・欲求を足すときに「触る場所」を
最小化するのが目的で、機能そのものを増やすのが目的ではない。

## 何が変わったか(要点)

- **対応表を 1 クラスに集約**: 以前は「Goal→Need」「Goal→PointType」「Goal→Motion」
  「各種の表示名」の switch が Brain / TargetSelector / CreatureAnimator に散っていた。
  これらをすべて新クラス **`CreatureActionCatalog`** に集約し、各層はそこを参照する。
- **CreatureAnimator がモーション決定を一元管理**: 「どの Goal でどのモーションを出すか」は
  対応表(`MotionForGoal`)にあり、Animator は無改造で新モーションに追従する。
- **AnimatorController 生成を表駆動化**: 生成コードを「モーション対応表」1 箇所に整理。
  新しいモーションは表に 1 行足すだけで状態が生える。
- **アセット直結の地点を追加**: セットアップが FoodBowl / **WaterBowl** / Bed /
  **ScratchSpot** を作る。制作中のアセットは仮メッシュごと差し替えれば使える。
- **Drink / Scratch を有効化**(Water / ScratchPost 地点付き)。Play は配線済みで休眠。

## 変更したクラス

| クラス | 変更内容 |
|---|---|
| **`CreatureActionCatalog`**(新規) | Goal⇔Need⇔PointType⇔Motion⇔表示名 の唯一の対応表 |
| `CreatureBrain` | 自前の対応 switch を廃し、Catalog を参照(判断ロジックはそのまま) |
| `CreatureTargetSelector` | `PointTypeForGoal` を廃し、Catalog を参照 |
| `ActionRunner` | 表示名・対象 Need の取得を Catalog 参照へ |
| `CreatureAnimator` | `DecideMotion` を `Catalog.MotionForGoal` で決定。表示名も Catalog へ |
| `CreatureCore` | Catalog を参照キャッシュし、各層へ注入 |
| `NeedsData` | `NeedCount` を 5→6(Scratchiness 追加) |
| `CreatureProfile` | 各配列を 6 要素へ。Thirst/Scratchiness を有効値に |
| `CreatureStatusDisplay` | HUD に Thirst / Scratchiness バーを追加 |
| `Goal` / `NeedType` / `MotionKind`(enum) | Scratch / Scratchiness / Drink・Play・Scratch・Groom・Stretch を追加 |
| `CreatureAISetup`(Editor) | Catalog を同梱、WaterBowl / ScratchSpot 生成、Animator 生成を表駆動化 |
| `CreatureAIStatusWindow`(Editor) | 「爪とぎ欲」ラベルを追加(行数は enum 長に自動追従) |

## 追加した enum と対応表

- **Goal**: `Scratch`(= 爪とぎ)を追加。
- **NeedType**: `Scratchiness`(= 爪とぎ欲、index 5)を追加。
- **MotionKind**: `Drink=5 / Play=6 / Scratch=7 / Groom=8 / Stretch=9` を追加
  (Groom / Stretch は状態だけ用意した予約枠。Goal に紐付ければすぐ Action になる)。
- **`CreatureActionCatalog`** の 6 表:
  `GoalForNeed` / `NeedForGoal` / `PointTypeForGoal` / `MotionForGoal` /
  `GoalName` / `NeedName` / `MotionName`。**新しい Action はこの 1 ファイルに行を足すだけ。**

## 手順書

### A. 新しいアセット(モデル/ベッド/ボウル等)を紐付ける

コード変更は不要。すべて Inspector で完結する。

1. **見た目(モデル)**: `Cat` 直下の仮 `Body`(カプセル)を消し、自分のモデルを
   `Cat` の子に置く。ルート(Cat)が動くので子も一緒に動く。
2. **地点アセット**(ボウル/ベッド等): シーンに置いたオブジェクトに `CreaturePoint` を
   付け、Inspector の **種類(PointType)** を選ぶだけ(例: WaterBowl → `水`)。
   起動時に自動で Registry へ登録され、猫の検索対象になる。仮メッシュを使う場合は、
   生成された `WaterBowl` 等の子メッシュを自分のモデルに差し替えてもよい。
3. **アニメーション**: `Animator` の `runtimeAnimatorController` を割り当てる
   (セットアップが生成する `CreatureAnimator.controller` を使うか、自作を割り当て)。

> **モデル付属の Animator について**: FBX モデルは自前の `Animator` を持って入ってくる
> ことが多い。`CreatureAnimator` は起動時に **Cat 配下の全 Animator を探査し、
> `MotionState` パラメータを持つものすべてへ値を反映する**ので、ルート/モデルの
> どちらに Controller を割り当てても動く(両方でもよい)。モデルを動かしたい場合は
> 「モデル側の Animator」に `CreatureAnimator.controller`(または `MotionState` を持つ
> 自作 Controller)を割り当て、各状態の Motion を自分のクリップに差し替える。
> 接続状態は頭上 HUD の `Motion : … (Anim×n)` で確認できる(n=0 は接続不良)。

> **他の動物(犬・鹿等)へ**: `CreatureActionCatalog` も各層も種族非依存。
> モデルと AnimatorController を差し替えれば同じ仕組みでそのまま動く。

### B. 新しいアニメーション(モーション)を足す

「対応表への追加だけ」で載る。

1. `MotionKind` に種別を 1 つ足す(値は末尾に連番。既存値は動かさない)。
2. `CreatureActionCatalog` の `MotionForGoal`(どの Goal で出すか)と `MotionName` に
   その種別を紐付ける。
3. AnimatorController に状態を足す:
   - 自動生成を使うなら `CreatureAISetup` の **モーション対応表**(`EnsureAnimatorController`
     内の `BuildMotionState(...)` の並び)に 1 行足す。
   - 既存 Controller を手編集するなら、AnyState → 新状態へ `MotionState == 値` の遷移を張る。
4. クリップ差し替えは Animator(Inspector)側で完結。CreatureAnimator のコードは触らない。

> Groom / Stretch は既に MotionKind と AnimatorController 状態が用意済み。Goal に
> 紐付ける(下記 D)だけで演出付きの Action になる。

### C. 新しい CreaturePoint(地点種別)を足す

1. `PointType`(`[Flags]`)に種別を 1 つ足す(値 `1 << n` は将来にわたり固定)。
   表示名は `[InspectorName("…")]` を付ける。予約済み枠(ScratchPost/Litterbox/
   Window/Sofa/Fireplace)を使うなら追加すら不要。
2. その種別を使う Action があるなら `CreatureActionCatalog.PointTypeForGoal` で紐付ける。
3. シーンのオブジェクトに `CreaturePoint` を付け、Inspector で種別・評価値・検索半径を設定。

### D. 新しい Action(Drink/Scratch/Groom/Stretch/Play 等)を足す

触るのは基本 **`CreatureActionCatalog` の 1 ファイル + enum + Profile 値** だけ。

1. `Goal` に Action を 1 つ足す(末尾に連番)。
2. 欲求で駆動するなら `NeedType` に欲求を 1 つ足し、`NeedsData.NeedCount` を +1、
   `CreatureProfile` の各配列を 1 要素伸ばす(未設定でも既定値で壊れない)。
   既存の欲求を使い回すなら不要。
3. `CreatureActionCatalog` の対応表に 1 行ずつ足す:
   `GoalForNeed` / `NeedForGoal` / `PointTypeForGoal` / `MotionForGoal` /
   `GoalName`(必要なら `NeedName` / `MotionName`)。
4. 地点を使う Action なら、その `PointType` の `CreaturePoint` をシーンに置く(手順 C)。
   専用モーションを出すなら AnimatorController に状態を足す(手順 B)。
5. 欲求の増加速度(`CreatureProfile.increaseRate`)を 0 より大きくすれば有効化。
   0 のままなら「配線済みだが休眠中(いつでも有効化できる)」状態。

→ これで Brain / TargetSelector / ActionRunner / CreatureAnimator は**無改造で**新 Action を扱う。

## 既知の割り切り(v1.0 から継続)

- Udon では enum 長を実行時取得できないため、`NeedsData.NeedCount` だけは Need 追加時に
  手で +1 する(唯一の二重管理点。ドキュメント化済み)。
- 地点を持たない「その場 Action」(毛づくろい等をワールド地点なしで実行)は未対応。
  現状は地点(CreaturePoint)を持つ Action として実装する。地点なし Action が必要に
  なったら ActionRunner に「その場実行」分岐を足す(層構造は不変)。
- AnimatorController は既存があれば再利用する。新モーションを反映したい既存プロジェクトは
  `Assets/CreatureAI_Generated/CreatureAnimator.controller` を削除してから再生成する。
